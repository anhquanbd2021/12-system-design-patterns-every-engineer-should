Wire-by-wire guide

One kill, two endings

Trip Line replays the same deterministic incident — baseline, kill, heal — under two protection modes. The only variable is whether a circuit breaker sits on the wire. Everything else on this page maps the lab's controls, and each of the 12 patterns, to the failure it prevents.

Honest limits. Ticks are simulated, not milliseconds; the fallback is counted, not rendered. The physics are simplified — the state machine is not.

Start here

What this demo proves

Set protection to none and dependency to dead, then Run: the pool saturates past 90%, the queue piles up, and at tick +20 timeouts begin — the cascade flag lights. Now switch protection to breaker and press Replay incident: the same kill trips the breaker open after 5 consecutive timeouts, every new request fails fast to the cached fallback, the pool drains, and two healthy probes close the breaker after the heal. Same failure, different ending — the pattern is the difference.

The controls

What each switch demonstrates

Control 01

Kill / Heal dependency

Flips the recommendations service between healthy, slow, and dead. Dead sockets never answer — calls park until the 20-tick timeout.

Proves
Failure is a property of the dependency, not of your code.
Key detail
Calls keep the mode they were admitted under — a parked socket does not revive on heal.
Control 02

Protection: breaker

Arms the closed → open → half-open state machine on the wire between caller and dependency.

Proves
The caller survives a dead callee — fallbacks, not parked threads.
Key detail
Trips at 5 consecutive timeouts, stays open 40 ticks, then 2 probes decide.
Control 03

Retry: immediate

Every 6 ticks an unanswered request resends — up to 4 calls each, whether or not the first has a worker. The retry storm.

Proves
Retries are load: the backlog balloons ~4× and outlives the heal.
Key detail
A request that resolves suppresses its retries — healthy baseline stays clean.
Control 04

Replay incident

Runs the scripted kill → heal scenario end-to-end with your current protection and retry settings.

Proves
Determinism — UI, CLI, tests, and the article GIF run the identical trace.
Key detail
10 baseline ticks, 60 dead, 80 heal — compare the two runs side by side.
Control 05

Trace strip

Charts pool saturation and average latency over the last 140 ticks, with timeout markers along the axis.

Proves
The cascade draws itself — saturation pins at 100% while latency climbs to timeout.
Key detail
Under the breaker the traces dip, the backlog sheds to fallback, and the wire recovers.
Control 06

/api/scenario

The server replays any scenario through the same lab module and returns the summary as JSON.

Proves
One model, three consumers — browser, CLI, and API agree tick-for-tick.
Key detail
Try /api/scenario?protection=breaker — cascadeTicks comes back 0.

The twelve

Every pattern is a failure it prevents

Pattern 01

Load Balancing

Health-checked spread across nodes — a balancer keeps any one node from being both the ceiling and the single point of failure.

Prevents
node death = outage; saturation while siblings idle.
Anti-pattern
DNS round-robin with no health checks.
Pattern 02

Cache-Aside

Check the cache first; a miss loads the database once and populates the key.

Prevents
every read hitting the DB — 3 ms becomes a 400 ms queue at 5,000 rps.
Anti-pattern
one uniform TTL — the minute-rollover dogpile.
Pattern 03

Circuit Breaker

The pattern this lab simulates. After N consecutive failures, stop calling, fail fast, probe to recover.

Prevents
the 2 a.m. cascade — callers parked on dead sockets.
Anti-pattern
a timeout alone is not a breaker.
Pattern 04

Retry + Backoff + Jitter

Transient faults deserve retries — with exponential delay, jitter, and a deadline.

Prevents
the retry storm flattening a recovering service.
Anti-pattern
a tight for loop that triples load mid-outage.
Pattern 05

Rate Limiting

Token bucket per client per window; over-limit gets 429 + Retry-After.

Prevents
one runaway job starving 400 well-behaved users.
Anti-pattern
a single global limit that still lets one client eat the bucket.
Pattern 06

Bulkhead

Partition pools per dependency or tenant so one consumer cannot drain the shared pool.

Prevents
the nightly batch starving checkout of connections.
Anti-pattern
one 200-connection pool for every call.
Pattern 07

API Gateway

One entry point owns TLS, authn, routing, and request shaping.

Prevents
JWT validation reimplemented twelve ways, one silently wrong.
Anti-pattern
clients calling services directly, concerns duplicated.
Pattern 08

Service Discovery

Services find each other by name through a registry; instances register and deregister as they scale.

Prevents
hardcoded hosts dying with the pod.
Anti-pattern
IP lists in env vars — the new replica nobody routes to.
Pattern 09

Pub/Sub

The broker buffers work so a slow or dead consumer never blocks or loses the producer's work.

Prevents
a dead email service rolling back a paid order.
Anti-pattern
publish-and-forget with no dead-letter queue.
Pattern 10

CQRS

Split the write model from the read model when their shapes and scales diverge.

Prevents
a dashboard GROUP BY locking the writes that make money.
Anti-pattern
CQRS on a three-table CRUD app.
Pattern 11

Sharding

Split data by a well-chosen key so no single database is the capacity ceiling.

Prevents
one Postgres at 2 TB, autovacuum losing the race.
Anti-pattern
sharding on created_at — every write lands on today's shard.
Pattern 12

Saga

A cross-service transaction is a chain of local transactions, each with a compensating undo.

Prevents
charged-but-unshipped orders stranded by a mid-chain crash.
Anti-pattern
pretending the distributed commit exists.

Limits

What this demo does not claim

  • Ticks are simulated steps — no real network, sockets, or wall clock.
  • One dependency, one pool, one breaker — real cascades fan out across hops.
  • The fallback is counted, not rendered — a real cache needs its own fill path.
  • "Slow" is a single latency below the timeout; real degradation is a spectrum.
  • A green breaker means "this call path is protected" — never "the system is correct".
